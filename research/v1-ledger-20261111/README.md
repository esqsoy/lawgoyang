# 원장 v1: 아홉 시험 2017~2026 (2026-11-11)

원장 v0(변호사시험·사법시험)에 나머지 일곱 시험의 10년 창(2017~2026) 매핑을 더했다. PRINCIPLES 1의 결정(26.11.11 영신 "추천대로 가자")대로 **매핑 먼저, 세트는 그다음**이다. 이 폴더는 v0과 v1을 비교한 결과다. 원장 파일은 `data/ledger/ledger-v1.json`, `sets-v1.json`이다(`python3 -I pipeline/ledger.py --v1`). 게임과 직검수 페이지는 아직 v0을 읽는다.

## 자료

- 원문은 저장소 밖 영신 아이클라우드 `40 법학/기출원문/`에 있다(그 폴더 README). 받는 스크립트는 `pipeline/exams/`에 있다(qnet_fetch.py, assembly_fetch.py, scourt_fetch.py, gosi_*.py).
- 배포용 HWP(법무사·법원행정고시 2017~2026, 입법고시 2018·2019)는 Polaris Office Editor에서 인쇄해 PDF로 만들었다. 입법고시 2017 일반 HWP도 같은 방법으로 PDF로 만들었다. 배포용 보호는 풀지 않았다.
- 글자는 `pipeline/exams/pdftext.swift`로 뽑았다. 스캔본(노무사 2017·2018·2021·2024 행정쟁송법, 변리사 2019·2020, 감정평가사 2017·2021·2024)은 맥 Vision OCR로 읽었다.
- 범위 밖이라 매핑하지 않은 과목: 형법·형사소송법·상법(법무사·법원행정고시, PRINCIPLES 1), 노동법·인사노무관리론(노무사), 특허법·상표법(변리사), 감정평가실무·이론(감정평가사).

## 조심할 점

- ~~원문 대조가 남았다~~ 26.11.12 마침(아래). 매핑만 했을 때는 41개 법령 129조가 저장소 원문 파일에 없어서, 발췌를 뺀 줄의 35%(896/2535)가 '확인 필요'였다.
- **공법 쟁점 묶음:** v0 공법 시범에는 BUNDLE 사전이 없다. 그래서 공법 묶음(법원행정고시·5급·입법고시·노무사·감정평가사)은 v0 공법 매핑에서 되풀이된 조문 조합을 각자 옮겨 적었다. 같은 쟁점이 묶음마다 조금 다르게 매핑됐을 수 있다.
- **출제 뒤 생긴 조문:** 오늘 법 기준(PRINCIPLES 2-1)이라 행정기본법·행정소송규칙 제9조처럼 출제 뒤 생긴 조문을 근거로 단 줄이 있다. 묶음에 따라 `current`에 메모를 달기도 하고(노무사·법원행정고시·입법고시·감정평가사), README에만 적기도 했다(5급). 세는 데는 차이가 없다.
- **감정평가사 2021:** 원본 스캔이 쪽마다 윗부분이 잘려 있어 문제 2의 물음 글이 없다. 사실관계와 참조 조문으로 짐작해 매핑했다. 원문을 다시 구하면 고친다.
- **서류작성:** 문제지에 물음 번호가 없어 작성 과제 단위로 설문을 나눴다(묶음 README). 소가·인지·세금·수수료처럼 서식 칸만 채우는 조문은 넣지 않았다.
- **v0에서 온 표기:** 사법시험 2011 공무원연금법 제46조, 2014 국세징수법 제24조(발췌)는 v0 매핑의 `current.article`이 '확인 필요'라는 글자다. 둘 다 창 밖 보관함이라 외울 조문에는 영향이 없다.
- 매핑은 모범답안 없이 Claude가 했다. 영신 검수 전이다.

## 원문 대조와 재판단 (2026-11-12)

- **원문:** Open API 키가 나와 `pipeline/fetch_api.py`로 v1 외울 조문 811개를 오늘 시행 중인 원문(시행일 법령, `target=eflaw`)으로 받았다(`sources/api/laws/`, 73개 법령). 웹 임시본과는 366조 가운데 365조가 같았다(PRINCIPLES 2).
- **번호 대조:** `verify_api.py`로 v1 매핑에서 발췌를 뺀 줄을 모두 대조했다(2,534줄). 조·항이 현행 법령에 없거나 삭제된 줄은 없었다. 틀린 번호를 일부러 넣어 검사기가 잡는 것도 확인했다.
- **재판단:** 묶음마다 하위 작업 하나가 '확인 필요' 줄을 현행 원문으로 다시 판단했다(`review.jsonl`, 줄마다 이유). 같은 기준서(`확실`: 그 조·항이 설문의 요건·효과의 근거임이 분명함)를 썼다.
  - 변리사 묶음은 판단 성향이 다른 두 하위 작업에 따로 맡겨 비교했다. 일치율은 68%(90줄 가운데 62줄)였다. 엇갈린 줄은 대부분 '설문의 전제나 청구원인 조문도 근거로 보나'에서 갈렸다. 그래서 두 판단이 모두 '확실'인 36줄만 올렸다.
  - 다른 일곱 묶음은 하위 작업 하나의 판단을 따랐다.
- **고침:** 재판단 때 '조문을 잘못 짚었다'는 표시 15줄과 '빠진 줄' 제안 3건이 나왔다. 두 하위 작업이 따로 판정했고, 둘이 합의한 것만 `corrections.jsonl`로 반영했다(바꾸기 10, 지우기 3, 더하기 5).
  - 판정이 엇갈린 3건은 이렇게 처리했다.
    - 민법 제640·641조, 시행규칙 제49조·제64조: 원래 줄을 두고 고칠 조문을 더했다.
    - 민법 제433조: 원래 줄이 틀렸다는 데만 합의돼 지웠다.
  - `pipeline/ledger.py`가 `review.jsonl`(확신도)과 `corrections.jsonl`(바꾸기·지우기·더하기)을 매핑 위에 얹는다. 매핑 파일과 build 스크립트는 고치지 않았다.
- **결과:** 발췌를 뺀 2,537줄 가운데 '확인 필요'는 256줄(10.0%)이다. 묶음별로 법무사 19, 서류작성 25, 법원행정고시 26, 5급 17, 입법고시 52, 노무사 36, 변리사 53, 감정평가사 28줄이다. 남은 줄의 이유는 근거 조문 판단이 갈림, 판례 의존, 학설 대립, 출제 뒤 법 개정 순으로 많다. 줄마다 이유는 각 묶음의 `review.jsonl`에 있다.
- **사람이 볼 곳(재판단에서 나온 것):**
  - 기준 하나: 설문의 전제나 청구원인이 되는 조문(예: 상계 항변 사안의 민법 제492조)도 '근거'로 셀지. 지금은 묶음마다 하나의 판단을 따랐고, 변리사만 엄격한 쪽(합의)이다.
  - 출제 뒤 법 개정으로 지금 답이 달라지는 줄:
    - 2023 입법고시 헌법 2: 2026. 3. 12. 재판소원 도입(헌법재판소법 제68조 제3항).
    - 2019 법무사 등기서류: 부동산등기규칙 제122조. 2024. 11. 29. 개정으로 근거가 제52조의2 쪽으로 옮겨 갔을 수 있다.
    - 노무사 2020 행정쟁송법 2, 감정평가사 2020 문제 2-2·2021 문제 3-1: 행정기본법 제36조 이의신청 뒤 제소기간.
  - 2024 법무사 등기서류 1: 법정상속등기 뒤 협의분할을 지분이전으로 볼지, 경정으로 볼지.
  - 판례 사건번호는 모두 기억에 기댄 것이라 판례 단계에서 원문을 확인해야 한다.
